# Folder documents and flat native workspace

An opened directory owns its PDFs, one shared root Markdown note, and new assets. PDF files retain their original directory hierarchy. `notes.md` is preferred. A sole existing root `.md` is opened in place, and other cases create `notes.md`. Existing image paths inside the workspace continue to resolve from their original locations. File-resource identity tracks a note renamed in Finder. Deleting a note externally preserves its missing state and stale saves create local recovery material.

Workspace records, sources, reading state, previous note versions, conversations and draft journals live under the existing per-workspace Application Support index. The filesystem remains the authority for visible documents. A new ordinary workspace creates its Markdown on disk and creates assets on demand. Its note has one draft identity across all selected PDFs. PDF switching rebinds the editor context while retaining its selection and undo history. Clean editor baselines use serialized Markdown independently from the on-disk revision, so harmless parser normalization does not masquerade as an unsaved user edit during external-file reloads.

## Migration

Legacy per-paper directories move from `.paper-reader` into the local record directory. Managed PDF copies move into the workspace hierarchy with collision-safe filenames. The chosen shared note retains existing content and receives the old note sections, with Markdown source links acting as idempotent migration markers. Legacy assets move into `assets/<paper ID>/`, preserving same-named images from different papers. Original note recovery copies stay in the local record directory. Migration plans persist before moving managed PDFs, permitting restart after an interrupted move. Unknown legacy files and recovery folders remain available.

New PDF links carry the relative filename, paper identity, page and rectangle. Links can select a different PDF in the same workspace. Application and detected Finder renames update their relative paths. The original folder's PDFs, Markdown and assets carry the research content across Macs. An explicit copy to a fresh cloud folder retains the original library.

## In-file PDF annotations

Highlight, Line, Square and Ink annotations use PDFKit's standard subtypes and geometry. App-owned identities and record metadata are embedded in each PDF annotation. The namespaced record identifies ownership even when earlier PDFKit versions omit the standard /NM name during serialization. Both canonical and legacy custom record keys are readable. Existing annotations from other editors are retained. The editable layer renders app-owned records once, and the saved original PDF renders them in other PDF readers. Highlight quadrilaterals, line endpoints and ink paths are persisted in annotation-local coordinates. The laser remains transient.

An owned helper process performs PDFKit reading and serialization on its main thread. Each save coordinates a read-modify-write of the latest PDF, checks the loaded annotation baseline and verifies the serialized annotations before atomically replacing the original. Temporary helper request files are removed. Persistent `annotations.json` files are migrated and removed after successful verified writing. Failed saves retain their pending records, prevent document/workspace switching or quitting from losing them, and expose a reload action. Reload retains the previous in-window snapshot in the undo stack. Exports reuse the same adapter and retain one copy of each annotation.

## Native appearance

The window and toolbar use system controls, with light-blue top chrome requested for the product. The PDF canvas uses a white background in light mode or a neutral dark background. Ordinary content panels share an 8 pt radius and small gutters. Divider lines, custom input outlines and PDF page shadows are removed. Sidebar and conversation split items use AppKit sidebar and inspector semantics. Toolbar and window geometry follow the system, and their title identifies the paper or folder. Hover transitions honor Reduce Motion. Offline note/chat styles follow the effective native light or dark appearance.

Apple's [toolbar guidance](https://developer.apple.com/design/human-interface-guidelines/toolbars) recommends standard components and reduced custom background styling. The light-blue titlebar is an explicit product customization. [Material guidance](https://developer.apple.com/design/human-interface-guidelines/materials) reserves Liquid Glass for functional navigation layers. The content panes use flat opaque surfaces.

## Validation

The source suite covers shared notes across nested PDFs, existing Markdown adoption and rename, missing-file recovery, idempotent legacy merging, colliding assets, shared-note export/copy, preservation of external annotations, legacy annotation migration, concurrent-save rejection and standard PDF annotation geometry. Native workspace checks use the actual editor, file tree, PDFKit and helper process to exercise root notes, original relative images, shared-note undo after PDF switching, source-driven paper switching and annotation persistence. Foreground/full-screen focus and the supplied seven-page PDF remain part of the reader regression suite.

Validation results and distribution status are recorded separately in RELEASE_VALIDATION.md. Actual two-Mac simultaneous editing, power failure and all unusual PDF producer formats remain outside completed coverage.

The completed local run passed 53 core tests, 12 editor tests, 150 foreground native checks per language with the external-paper regression enabled, and a subsequent 29 workspace checks per language after the toolbar/page-badge refinements. Dark-appearance reader checks also passed 150 per language in an earlier scoped run. The final workspace checks verify the actual native/editor appearance agreement. The source adds a workspace process lease and a cross-version startup guard. Duplicate source-path records are consolidated after note migration, with their original directories moved into local recovery storage. Fractional annotation geometry retains its exact stored record within PDF numeric rounding tolerance.

During local UI inspection, an unintentionally started development instance overlapped an older production instance, creating duplicate indexes. Both were closed, a full workspace/index recovery snapshot was taken, and the active index was consolidated to its original 27 unique PDF paths. All 108 pre-existing migrated-note archives remained byte-identical in active or recovery storage. One PDF received its two legacy line annotations, its seven original page-content renderings remained byte-identical through Quartz, and the active annotation sidecars were removed after verified persistence. User documents and recovery material remain local and are excluded from Git and release assets.

Version 0.4.6 binds page-only AI note citations to their originating PDF. Legacy per-paper notes are normalized before merging. Already-merged sections with application migration markers receive a one-time coordinated repair, preserving the complete prior Markdown in local recovery. Unmarked legacy citations retain their original text because their originating paper cannot be established. Page-only document links navigate to the page without a fabricated capture rectangle. Native workspace coverage now includes 30 checks per language.

The final Ask AI action is icon-only beside the reading tools in the PDF toolbar, following the user’s final placement and labeling instruction. It stays directly available in compact and expanded toolbar layouts. Its tooltip includes the command name and configured shortcut.
